# Plan A7: Drop `vehicleSpawned` Broadcast in OnVehicleSpawned

**Status**: Approved 2026-05-27 (pending execution).
**Scope**: Delete the `sendHighlightedWorldLogMessage` call at the end of `OnVehicleSpawned`. Conquest gates this exact broadcast behind a feature flag and disables it in production. Helis equivalent: remove it.

> First action per [`AGENTS.md`](../AGENTS.md): read [`AGENTS.md`](../AGENTS.md) and [`design_doc/heli_issues_design.md`](./heli_issues_design.md) Section 0.

---

## Context

Reported runtime error: **"Received undefined values as arguments"** — still firing 2 instances at round start on v0.634, after v0.632–v0.634 closed the other suspect sources (roster validity, RemoveEquipment empty-slot, all 14 Player-as-format-arg call sites + 3 subtitle extra-arg drops).

The remaining strong hypothesis is the `vehicleSpawned` broadcast at [src/index.ts:665-672](../src/index.ts#L665):

```ts
const pos = mod.GetVehicleState(eventVehicle, mod.VehicleStateVector.VehiclePosition);
...
const x = Math.floor(mod.XComponentOf(pos));
const z = Math.floor(mod.ZComponentOf(pos));
sendHighlightedWorldLogMessage(
    mod.Message(mod.stringkeys.twl.messages.vehicleSpawned, teamNameKey, x, z),
    true,
    undefined,
    mod.stringkeys.twl.messages.vehicleSpawned
);
```

Evidence supporting this as the source:
- **Count match**: at round start with the 1v1 default matchup, 2 vehicles spawn → 2 OnVehicleSpawned events → 2 broadcasts. Exactly the "2 instances" the user reports.
- **NaN risk**: `pos` is read via `mod.GetVehicleState(VehiclePosition)` AFTER an `await mod.Wait(0.2)` retry path. If pos is invalid at that moment (engine state not settled after spawn), `mod.XComponentOf(pos)` returns undefined/NaN. `Math.floor(undefined)` = NaN. Passing NaN as `mod.Message`'s format arg is the most plausible "Received undefined values" source.
- **Conquest precedent**: [conquest/src/index/vehicle-events.ts](../../conquest/src/index/vehicle-events.ts) gates this exact broadcast behind `FEATURE_PERF_DIAG && State.admin.perfDiagEnabled`. Conquest hit this pattern and explicitly disabled the broadcast in production via flag. Helis doesn't have `FEATURE_PERF_DIAG`, so the simplest equivalent is to drop the broadcast.

The broadcast is debug-style ("Vehicle spawned for {team} at X:.../Z:..."). Players don't need spawn coordinates for gameplay; vehicle registration narration on entry (separate broadcast, kept) is what they actually use.

## Conquest reference pattern

[conquest/src/index/vehicle-events.ts](../../conquest/src/index/vehicle-events.ts):
- The vehicleSpawned broadcast is gated behind `FEATURE_PERF_DIAG`.
- v1.380 changelog: "Emitter at vehicle-events.ts:84-89 wrapped in `FEATURE_PERF_DIAG && State.admin.perfDiagEnabled` gate. Off in production (compile-time strip); toggleable via existing perfDiag admin button."

For Helis without that flag machinery, the cleanest Conquest-aligned port is to delete the broadcast entirely. If a future feature flag is added to Helis, this can be re-gated rather than dropped.

## Why this is risk-free

- **Gameplay impact**: zero. The broadcast was debug-style info ("Vehicle spawned for WEST at X:-790/Z:244"). Players don't reference it for gameplay decisions.
- **Registration messaging**: unaffected. The "vehicle registered for {team} by {player}" broadcast on entry (separate path, kept) is what players actually use to verify scoring.
- **String key**: `mod.stringkeys.twl.messages.vehicleSpawned` remains in `strings.json` (orphaned but harmless). Not editing `strings.json` per AGENTS.md (no string-edit approval requested).
- **No new state, no new constants, no per-tick work.**

## Performance

- **Per-spawn cost**: 1 fewer engine call (`mod.Message` construction + `sendHighlightedWorldLogMessage` wrapper) per vehicle spawn.
- **Per-tick**: unchanged. OnVehicleSpawned is event-driven, fires only on vehicle spawn.
- **Bundle**: small decrease (~150-200 bytes after comment-strip).
