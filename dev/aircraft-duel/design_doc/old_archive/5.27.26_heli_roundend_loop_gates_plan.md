# Plan A4: Phase-Gate Pregame Loop Functions Against GameOver/Cleanup

**Status**: Approved 2026-05-27 (pending execution).
**Scope**: Extend the guard in `checkTakeoffLimitForAllPlayers` and `applyAutoReadyForAllPlayers` to skip during `GameOver` phase and during `cleanupActive`. Both are pregame-only by design; their current guard only excludes Live.

> First action per [`AGENTS.md`](../AGENTS.md): read [`AGENTS.md`](../AGENTS.md) and [`design_doc/heli_issues_design.md`](./heli_issues_design.md) Section 0.2.

---

## Context

Reported runtime error: **"ERROR REPORTED BY GETSOLDIERSTATE WHILE: Failed to apply action to player due to player not being deployed"** — appearing at end of round when a player dies. Plan A2 (v0.632 deploy-settle grace) closed the post-deploy race; this is the symmetric **post-death undeploy race**.

Race window:
1. Player dies (vehicle destroyed). `OnVehicleDestroyed` fires, may trigger `endRound` if kill target reached.
2. `endRound` sets `State.round.phase = RoundPhase.GameOver`.
3. Engine begins internal undeploy of the dead player; `OnPlayerUndeploy` event has not yet fired, so `State.players.deployedByPid[pid]` is still `true` (stale).
4. The 1-second master loop fires.
5. `checkTakeoffLimitForAllPlayers` and `applyAutoReadyForAllPlayers` execute their guards:
   - `if (State.match.isEnded) return;` — false during round-end (match not over yet).
   - `if (isRoundLive()) return;` — false (phase is GameOver, not Live).
   - **Both functions proceed and iterate all players.**
6. For the dead player: `isPlayerDeployed(p)` passes (cache stale-true). `safeGetSoldierStateVector(p, GetPosition)` or `safeGetSoldierStateBool(p, IsInVehicle)` calls the engine on an actually-undeployed player.
7. Engine logs "GETSOLDIERSTATE... player not being deployed", throws.
8. Safe-wrapper catch block flips cache to false (self-healing) — but the engine log is already allocated.

Both functions are pregame gates (`checkTakeoffLimit` enforces "no aircraft takeoff before round start"; `applyAutoReady` flips ready state when a player enters a vehicle in main base). Neither has any purpose during GameOver / cleanup. The fix is to tighten the guard to "run only during NotReady".

This is a P0-2 family bug. Same heap-pressure mechanism as #94 → #109.

## Conquest reference pattern

Verified 2026-05-27. Conquest uses a `lifecyclePhase` string at [conquest/src/conquest-flow.ts:101](../../conquest/src/conquest-flow.ts#L101) and gates work explicitly on phase transitions. ## Diff 1 — `checkTakeoffLimitForAllPlayers`

[src/ready-dialog.ts:3398-3401](../src/ready-dialog.ts#L3398):

```ts
// BEFORE
function checkTakeoffLimitForAllPlayers(): void {
    if (State.match.isEnded) return;
    if (isRoundLive()) return;

// AFTER
function checkTakeoffLimitForAllPlayers(): void {
    if (State.match.isEnded) return;
    // Skip during any phase other than pregame NotReady, and during round-end cleanup.
    // This eliminates SoldierState reads on players whose deployedByPid cache is stale
    // during the post-death undeploy race (Conquest #94 family).
    if (State.round.phase !== RoundPhase.NotReady) return;
    if (State.round.flow.cleanupActive) return;
```

## Diff 2 — `applyAutoReadyForAllPlayers`

[src/ready-dialog.ts:3485-3486](../src/ready-dialog.ts#L3485):

```ts
// BEFORE
function applyAutoReadyForAllPlayers(): void {
    if (State.match.isEnded || isRoundLive()) return;

// AFTER
function applyAutoReadyForAllPlayers(): void {
    if (State.match.isEnded) return;
    // Match the pregame-only gate pattern: skip during GameOver and cleanupActive
    // to avoid SoldierState reads on just-died players (Conquest #94 family).
    if (State.round.phase !== RoundPhase.NotReady) return;
    if (State.round.flow.cleanupActive) return;
```

## Why this is risk-free

- **NotReady phase**: both new checks pass (phase === NotReady, cleanupActive false). Functions run as before. Identical behavior.
- **Live phase**: old guard skipped via `isRoundLive()`. New guard skips via `phase !== NotReady`. Same end behavior (skip).
- **GameOver phase**: old guard ran the function. New guard skips. **This is the intended behavior change** — these are pregame functions; running during GameOver was a latent bug.
- **Cleanup window**: phase may have flipped back to NotReady before cleanup finishes. Old guard ran. New `cleanupActive` check catches this. **Intended behavior change**.
- **No new state, no new constants, no new imports.**

## Performance

- **Per-call cost added**: 2 O(1) checks (enum comparison + boolean property access). Negligible.
- **Per-tick impact**: these functions run from the 1Hz master loop (not per-tick). The added gates are evaluated 1× per second per function.
- **Skip-path savings**: when the new gates fire (GameOver / cleanup), the functions early-return instead of running `mod.AllPlayers()` + `CountOf()` + N-player iteration with soldier-state reads. **Performance strictly improves** during GameOver / cleanup; unchanged during NotReady and Live.
