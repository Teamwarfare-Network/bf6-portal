**Approved**: 2026-05-27. **Status**: implemented v0.631.
**Scope**: Add a single safe wrapper around `mod.UndeployPlayer` and replace all 4 call-site invocations across 3 files. No behavior change beyond eliminating engine error logs on already-undeployed players. Reference: Conquest #36 (v1.071) and #39 (v1.147).

## Context

Conquest fixed this exact pattern at **v1.071 (#36 `CQ_Bug_UndeployPlayer_On_Undeployed`)**. The mechanism: calling `mod.UndeployPlayer` on an already-undeployed player generates an engine error log, and each engine error log allocates JS heap. Individually cosmetic; cumulatively a heap-pressure contributor that fed the 16-player crash (#109).

Helis has 3 call sites; 1 is fully guarded, 2 are not. None use a centralized helper.

Implements improvement plan item **P0-2 (`mod.UndeployPlayer` portion only)**. The rest of P0-2 — `mod.RemoveEquipment` and `mod.GetPlayerVehicleSeat` guards — gets its own plan.

## Conquest reference patterns

Grepped Conquest's source for every `mod.UndeployPlayer(` call. The conventions Conquest landed on after #36:

| Pattern | Where in Conquest | Use case |
|---|---|---|
| `try { mod.UndeployPlayer(p); } catch {}` | [conquest/src/boundary/enforcement.ts:284-286](../../conquest/src/boundary/enforcement.ts#L284), [spectator/spectator-action.ts:560-562](../../conquest/src/spectator/spectator-action.ts#L560), [vehicles/hq-deploy.ts:337](../../conquest/src/vehicles/hq-deploy.ts#L337), [vehicles/hq-deploy.ts:345](../../conquest/src/vehicles/hq-deploy.ts#L345) | Predominant pattern; safe default. |
| `if (!isPlayerDeployed(p)) continue;` precheck (no try/catch) | [conquest/src/ready-dialog/countdown-flow.ts:31-33](../../conquest/src/ready-dialog/countdown-flow.ts#L31) | Loop-context precheck; cleanest. |
| Function-wide `try { … } catch {}` | [conquest/src/index/player-deploy.ts:5-10](../../conquest/src/index/player-deploy.ts#L5) | The `deferForcedUndeploy` analog. |

**Conclusion**: Conquest converged on **try/catch as the primary defense, with `isPlayerDeployed` precheck as a complementary optimization**. The precheck avoids the engine call entirely (cheapest); the try/catch swallows the engine log allocation when the precheck races.

Helis already has `safeGet*` helpers in [src/state.ts](../src/state.ts) (`safeGetSoldierStateBool`, `safeGetSoldierStateVector`, `safeGetObjId`, `safeGetPlayerId`). Adding `safeUndeployPlayer` fits cleanly into that pattern.

## The helper

```ts
// Safe wrapper around mod.UndeployPlayer.
// - Skips the engine call entirely if the player is already undeployed
//   (precheck eliminates the cosmetic engine error log per Conquest #36/#39 pattern).
// - try/catch protects against the engine throwing during transient deploy state.
// - Returns true if the engine call was attempted; false if precheck skipped it.
function safeUndeployPlayer(player: mod.Player | null | undefined): boolean {
    if (!player || !isPlayerDeployed(player)) return false;
    try {
        mod.UndeployPlayer(player);
        return true;
    } catch {
        return false;
    }
}
```

## Per-site changes

### Site 1 — `deferForcedUndeploy` ([src/index.ts:300-309](../src/index.ts#L300))

Keeps the function-wide try/catch (matches Conquest's `player-deploy.ts:5-10` analog) but delegates the `mod.UndeployPlayer` call to the helper. The helper's internal `isPlayerDeployed` precheck + try/catch is the new defense.

### Site 2 — `forceUndeployPlayer` ([src/team-switch.ts:181-189](../src/team-switch.ts#L181))

Double-undeploy retry pattern is preserved (and is the right thing per Conquest [interaction/actions.ts:227-230](../../conquest/src/interaction/actions.ts#L227)). The helper makes the second call cheaply no-op via the precheck if the first succeeded → no engine log on the common success path. This is the highest-impact site in the change.

### Site 3 — `scheduleRoundEndCleanup` loop ([src/round-flow.ts:215-235](../src/round-flow.ts#L215))

Replace the inline `try { mod.UndeployPlayer } catch { continue }` with `safeUndeployPlayer(player)`. The `continue` is dropped because `State.players.deployedByPid[pid] = false` and `setUIInputModeForPlayer(player, false)` are both safe to run even if the engine UndeployPlayer call was skipped — and during round-end cleanup we want them to run unconditionally for state hygiene. Behavior change is intentionally additive: more thorough cleanup, fewer log allocations.

## Why this is risk-free

- **Success path**: unchanged. The engine still receives `mod.UndeployPlayer(player)`.
- **Already-undeployed path**: previously fired an engine log; now silently skips. **This is the desired behavior change** — the engine log was the bug.
- **Engine-throw path**: previously caught at the caller's try/catch (or crashed if no try/catch on site 2); now uniformly caught inside the helper.
- **State writes preserved**: all `State.players.deployedByPid[pid] = false` writes stay where they were.
- **No new dependencies, no new constants, no new imports.**
