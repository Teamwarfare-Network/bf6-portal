## 1. Context and goals

Aircraft-duel inherits a helis-only experience where vehicle composition is controlled by a single "matchup count" knob (1v1-4v4) plus a single per-team vehicle-type cycler. The user is replacing that with **direct per-spawner control**: every spawner slot has its own knob that cycles `[Off, vehicle, vehicle, ...]`. This collapses "how many" and "which vehicle" into one control per slot, makes count implicit (number of non-Off knobs), and naturally supports any mix of helis and planes.

**Three features:**

1. **Add planes** - 2 plane spawner slots per team with static per-map anchor positions (defaults per map).
2. **Per-spawner vehicle knobs on the Ready Dialog** - one knob per spawner (4 heli + 2 plane per team), each directly selecting that slot's vehicle or Off.
3. **New mode selections** - presets that set the full per-knob selection (helis-only, planes-only, mixed), with aircraft-oriented naming and the right context rules (ceiling/overtime).

**Model change vs. v1 of this plan:** v1 used two count knobs + two type cyclers. v2 uses one knob per spawner (Conquest's `vehicleSelectionIndexByKey` model). This **removes** `matchupPresetIndex` (vehicle role), `vehicleIndexT1/T2`, and the count knobs; it **keeps** best-of, players/side (auto-start), vehicle-HP, soldier-HP, aircraft-ceiling, and the game-mode cycler.

## 4. Architecture (aircraft-duel adaptation)

### 4.1 Knobs and option lists

Knob keys (12 total): `team{1,2}Heli{1..4}`, `team{1,2}Plane{1,2}`.

Option lists (`ReadyDialogVehicleOption = { label: number; vehicle?: mod.VehicleList }`):
- `HELI_T1_OPTIONS` (NATO): `[Off, MapDefault, AH64, Eurocopter, UH60, AH6M]`
- `HELI_T2_OPTIONS` (PAX): `[Off, MapDefault, AH64, Eurocopter, UH60_Pax, AH6M_Pax]`
- `PLANE_OPTIONS` (shared): `[Off, F16, F22, JAS39, SU57]`

"Off" = `{ label: <noSpawn key>, vehicle: undefined }` at index 0. "Map Default" is a heli-only sentinel option resolved at spec-build time to the anchor's authored vehicle (`team{1,2}HeliSpawns[i].vehicle`); store it as a distinct option whose `vehicle` is a sentinel (e.g. `undefined` is taken by Off, so use a dedicated marker like a `mapDefault: true` flag on the option or a reserved enum and special-case it in the resolver).

### 4.2 State

`State.round.modeConfig.vehicleSelectionIndexByKey: Record<string, number>` (pending) + `...confirmed.vehicleSelectionIndexByKey` (confirmed). Seeded at `applyMapConfig` from the default game mode's preset. **Remove** `vehicleIndexT1/T2`, `vehiclesT1/T2`, and `matchupPresetIndex` from the vehicle path (keep `autoStartMinActivePlayers` - it is the human auto-start gate, unrelated to vehicle count).

### 4.3 Spawn pipeline

- **Slot family**: add `family: "heli" | "plane"` to `VehicleSpawnerSlot` ([state.ts:898](../src/state.ts#L898)); `addVehicleSpawnerSlot` ([vehicles.ts:216](../src/vehicles.ts#L216)) takes `family`. `startVehicleSpawnerSystem` ([vehicles.ts:572](../src/vehicles.ts#L572)) creates 4 heli + 2 plane slots per team from the map's heli/plane anchors.
- **Spec build**: replace `refreshVehicleSpawnSpecsFromModeConfig` ([strings.ts:65](../src/strings.ts#L65)) with a knob-driven builder (mirror `buildSelectedVehicleSpawnSpecsFromKnobs`): for each knob, resolve selected vehicle; Off -> slot disabled (omit); Map Default -> anchor's authored vehicle; else explicit. Produces `TEAM1/2_VEHICLE_SPAWN_SPECS` (helis) and `TEAM1/2_PLANE_SPAWN_SPECS`.
- **Apply to slots**: `applyVehicleSpawnSpecsToExistingSlots` ([strings.ts:86](../src/strings.ts#L86)) re-tags each slot's `vehicleType` by `family` + `slotNumber`; a slot with no matching active spec (knob Off) gets disabled via the existing `setSpawnerSlotEnabled(slotIndex, false)`.
- **Enablement**: replace `applySpawnerEnablementForMatchup` ([vehicles.ts:273](../src/vehicles.ts#L273)) count logic with "enabled = knob is not Off." Keep the sequential-spawn token machinery.

### 4.4 Kills target + symmetric constraint (D3)

- Active count per team = number of non-Off knobs (heli + plane) for that team in the **confirmed** selection.
- On Confirm: if `t1ActiveCount !== t2ActiveCount`, **block** the apply and show a red notice (mirror the existing ceiling-lock / restart-needed per-pid notice pattern in [ready-dialog.ts](../src/ready-dialog.ts)); leave pending dirty so the user can fix it.
- When counts match, `State.round.killsTarget = activeCount`. The admin round-kills-target override knob remains and can diverge after the fact.

### 4.5 Modes / presets (feature 3)

Each game-mode preset is a `buildReadyDialogVehicleSelectionIndexByGameMode`-style function returning a full `vehicleSelectionIndexByKey` (which knobs on, which vehicles, symmetric counts). `applyReadyDialogModePresetForGameMode` ([ready-dialog.ts:3562](../src/ready-dialog.ts#L3562)) sets pending selections (no spawn until Confirm). `isReadyDialogModePresetActive` ([ready-dialog.ts:3533](../src/ready-dialog.ts#L3533)) and `detectAndApplyMatchingPreset` ([ready-dialog.ts:3510](../src/ready-dialog.ts#L3510)) compare the full selection map instead of `matchupPresetIndex` + `vehicleIndexT1/T2`.

### 4.7 Roster-embedded knob layout + map capability (v3)

**Layout (D10/D12).** The 12 vehicle knobs live INSIDE the two roster boxes, not in the top-right config column. Per team box:

```
            <CENTERED TEAM NAME>           <- WEST / EAST, centered above the section
   Jet 1      Heli 1      Heli 3           <- knob grid, top of the box
   Jet 2      Heli 2      Heli 4
   --------------------------------
   <player roster rows, now max 12>
```

- T1's grid in the WEST box, T2's grid in the EAST box (layout not flipped; only viewer-relative colors flip per the kickoff doc rule).
- Reference anchors: roster boxes + team-name labels are built in `createTeamSwitchUI` ([ready-dialog.ts](../src/ready-dialog.ts)); roster rows loop on `TEAM_ROSTER_MAX_ROWS` at [ready-dialog.ts:1601](../src/ready-dialog.ts#L1601) and roster sizing at [hud.ts:559](../src/hud.ts#L559).

**Roster cap (D11).** `TEAM_ROSTER_MAX_ROWS: 16 -> 10` in [types.ts:53](../src/types.ts#L53), and `AUTO_START_MIN_ACTIVE_PLAYERS_MAX: 8 -> 10` ([types.ts:200](../src/types.ts#L200)). The roster constant drives 7 sites: ready-dialog roster build ([1601](../src/ready-dialog.ts#L1601)) + preset-active count ([2521](../src/ready-dialog.ts#L2521)), team-switch roster ([team-switch.ts:293](../src/team-switch.ts#L293)), hud roster ([hud.ts:559](../src/hud.ts#L559), [716](../src/hud.ts#L716)), and the **victory dialog roster** ([hud-dialog-lazy.ts:772/806/875](../src/hud-dialog-lazy.ts#L772)). Changing the constant resizes all; verify the victory dialog still fits 10 rows (its container heights are sized from roster-row constants in [types.ts:576-583](../src/types.ts#L576)). Crew-capacity rationale: 10 = 4 helis x 2 crew + 2 jets x 1.

**Map capability (D13).** Add a "Not on this Map" state per knob category, determined by MapConfig anchor presence:
- Heli knob: `team{1,2}HeliSpawns` exists on every map -> always selectable.
- Plane knob: selectable only when `team{1,2}PlaneSpawns` is present and non-empty for the active map. Otherwise the knob is **locked** to a "Not on this Map" label, non-cyclable, and resolves to no spawn (contributes 0 to the active count and the symmetric-count check).
- Implementation: a `getReadyDialogKnobCapability(knobKey)` helper reads `ACTIVE_MAP_CONFIG` anchor presence. The readout renders "Not on this Map" + disables the dec/inc buttons for that knob (mirror the live-locked button treatment in conquest `mode-config-readout.ts`). The knob-driven spec builder already omits Off/undefined slots, so an unsupported plane knob simply never spawns.
- **Mode gating (D15)**: the game-mode cycler hides plane-inclusive modes on jetless maps. Add a `mapSupportsPlanes()` check (true when the active map has non-empty `team{1,2}PlaneSpawns`); `setReadyDialogGameModeIndex` skips plane/mixed modes when false, and `applyMapConfig` snaps off a plane mode if the new map can't run it.
- Initial map coverage: **only Operation Firestorm** has plane anchors (from Conquest); all other maps show jets as "Not on this Map" and hide plane modes until authored.
