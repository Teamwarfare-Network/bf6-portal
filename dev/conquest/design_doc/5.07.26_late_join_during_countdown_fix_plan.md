## Context

**The bug.** A player late-joining during the live countdown (20..19..LIVE!) gets initialized with `State.players.readyByPid[pid] === undefined` (the join handler never explicitly sets it). Every countdown animation frame re-validates `areAllActivePlayersReady()`. The undefined ready value evaluates falsy, validation returns false, and the countdown async coroutine bails. **The bail path is incomplete** — it clears `State.round.countdown.isActive` and hides the visual, but does NOT call `mod.EnableAllPlayerDeploy(true)` or reset `State.conquest.lifecyclePhase` from `"COUNTDOWN"` back to `"NOT_READY"`. Result: every player who was waiting for LIVE is now stuck on the deploy screen with the deploy gate closed and no way back to ready-up.

**User's stated direction:** the countdown should be uncancellable once it begins; the "ready" concept no longer applies once the countdown has begun.

**Why this is the right fix shape (vs. patching the bail path).** Patching the four early-bail paths in `runPregameCountdown` to call full cleanup would be a larger change and would still leave the ready-state-flips-cancel-countdown UX surface intact — which the user explicitly rejects. Removing the not-ready check makes the countdown uncancellable-by-ready-state, eliminating the trigger that exposes the bail-path cleanup gap. The bail-path gap becomes dead code in practice (token-mismatch bails only fire after `cancelPregameCountdown` already cleaned up).

## Pre-flight findings

**Root cause location:** [`src/ready-dialog/countdown-flow.ts:61`](../src/ready-dialog/countdown-flow.ts#L61) inside `isPregameCountdownStillValid`:

```ts
if (!force && !areAllActivePlayersReady()) return false;
```

This line is the cancel trigger. Removing it makes the countdown only abortable by:
1. Token mismatch (admin reset path via `triggerFreshMatchSetup` → `cancelPregameCountdown` → `token++`; that path already does full cleanup).
2. Match ended / match already live (defensive guards; shouldn't fire mid-countdown in practice).

**Bail-path gap (latent, becomes dead code post-fix):** [`runPregameCountdown` at lines 91-94, 111-114, 131-134, 138-141](../src/ready-dialog/countdown-flow.ts#L91) only clear `State.round.countdown.isActive = false` and call `hidePregameCountdownForAllPlayers()`. They miss `mod.EnableAllPlayerDeploy(true)` and `State.conquest.lifecyclePhase = "NOT_READY"`. After the fix, the only realistic trigger (token mismatch from admin reset) has its cleanup handled by `cancelPregameCountdown` itself, so the bail-path gap is no longer reachable in practice. Leaving the bail paths as-is is the minimum-scope choice; they remain valid as defensive bails for the rare match-ended-mid-countdown case.

**Late-joiner deploy lifecycle (post-fix):**
- Late-joiner joins during countdown. Deploy gate is `false` from [`startPregameCountdown` line 42](../src/ready-dialog/countdown-flow.ts#L42).
- Late-joiner's `readyByPid[joinPid]` stays undefined. **No longer matters** — the cancel check is gone.
- Countdown completes normally. [`runPregameCountdown` line 153](../src/ready-dialog/countdown-flow.ts#L153) fires `mod.EnableAllPlayerDeploy(true)` globally → late-joiner can now deploy.
- LIVE transition runs `startMatch` (line 154) and the late-joiner gets the standard LIVE deploy flow.

**User-confirmed scope decisions (via AskUserQuestion 2026-05-07):**
- Minimum-scope fix: just remove the not-ready cancel. Don't disable ready-button during countdown. Don't block team-swap during countdown.
- Late-joiner experience: sit on deploy screen, auto-enabled at LIVE (relies on existing `EnableAllPlayerDeploy(true)` at countdown-flow.ts:153).
- File the issue in conquest_issues.md as the first step.

**Ready button click during countdown (clarifying note from user follow-up):**
- A late joiner CAN open the ready dialog (via interact triple-tap) and click READY during countdown.
- Post-fix this is harmless: the click sets `readyByPid[joinPid] = true`, then the click handler calls `tryAutoStartMatchIfAllReady` which returns early on `State.round.countdown.isActive === true` ([`auto-start.ts:12`](../src/ready-dialog/auto-start.ts#L12)). Countdown unaffected.
- The UX gap is purely cosmetic — late joiner sees a clickable button that does nothing visible. Fixing this is out of scope per minimum-scope choice; flagged as follow-up #1 below.

### Step 2 — Apply fix in code

[`src/ready-dialog/countdown-flow.ts:61`](../src/ready-dialog/countdown-flow.ts#L61) — single-line removal:

**Before:**
```ts
function isPregameCountdownStillValid(expectedToken: number, force?: boolean, allowRoundActive?: boolean): boolean {
    if (expectedToken !== State.round.countdown.token) return false;
    if (State.match.isEnded) return false;
    if (!allowRoundActive && isMatchLive()) return false;
    if (!force && !areAllActivePlayersReady()) return false;
    return true;
}
```

**After:**
```ts
function isPregameCountdownStillValid(expectedToken: number, force?: boolean, allowRoundActive?: boolean): boolean {
    if (expectedToken !== State.round.countdown.token) return false;
    if (State.match.isEnded) return false;
    if (!allowRoundActive && isMatchLive()) return false;
    // v1.474 (CQ_Bug_115): ready-state no longer cancels the countdown. Once started, only admin
    // reset (token mismatch via cancelPregameCountdown) or match-end can abort. Late-joiners with
    // undefined readyByPid previously cancelled it; the bail paths leak EnableAllPlayerDeploy(false)
    // → all watchers locked out.
    return true;
}
```

The `force` parameter is retained for signature stability with the rest of the file (still passed by callers). It is no longer consumed inside the function — out-of-scope cleanup flagged below.
