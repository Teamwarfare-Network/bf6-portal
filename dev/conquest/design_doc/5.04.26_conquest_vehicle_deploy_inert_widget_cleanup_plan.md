# Vehicle Deploy Menu — Inert Widget + Dead-Cleanup Sweep

**Status:** **PROPOSED — awaiting approval (2026-05-04).** Single ship, 3-file delete pass. Removes the Blur+Fill widgets that are constructed every match but never rendered, plus 7 stale dead-cleanup hooks for never-created Checkbox* widgets, plus 5 orphan constants. Per-pid widget reclaim ~18 widgets; zero observable visual change in-game.

This is a follow-up to the v1.463 shadow removal (see [`5.04.26_conquest_vehicle_deploy_shadow_removal_plan.md`](./5.04.26_conquest_vehicle_deploy_shadow_removal_plan.md)) — same shape of cleanup, comparable scale, *lower* risk because the affected widgets have no visible footprint today.

## Context

**What:** delete three categories of dead/inert code from the vehicle deploy timer HUD family. Categories enumerated below in §Pre-flight findings, summarised here:

- **Tier 1 — Inert button-level Blur+Fill widgets.** Constructed at warm-up, parented into the Border container, but every visibility-toggle path sets them to `false`. Verified by exhaustive grep over `safeSetUIWidgetVisible(... blur|fill ..., true|visible)` in the file. Six widget kinds: `spawnButtonBlur`, `spawnButtonFill`, `groundButtonBlur`, `groundButtonFill`, `closeButtonBlur`, `closeButtonFill`. Total **~18 widgets/pid** reclaim.
- **Tier 2 — Stale dead-cleanup hooks.** `deleteVehicleDeployTimerHudArtifactsForPid` calls `deleteAllReusableTimerWidgetsByName` against 7 widget names that no creation site in the project produces (Checkbox* family). Same shape as the `CheckboxMarkShadow` line we removed in v1.463. Pure code deletion, **zero runtime widget reduction** (the cleanup function is already a no-op for these names).
- **Tier 3 — Orphan constants in `foundation/ui-layout.ts`.** Three constants used only by Tier 1 widgets become orphan after the widget removal. Two more are already orphan today.

**Why:**
1. Heap reclaim — ~18 widgets/pid stacks on the v1.463 reclaim of ~17 widgets/pid for cumulative impact in the same direction Wave 6/7 optimization work is pursuing.
2. Code clarity — readers should be able to grep for "Blur" or "Fill" widget names and find load-bearing widgets, not vestigial scaffolding.
3. Future maintenance — every refactor of the deploy HUD currently has to navigate around inert widgets and dead cleanup hooks. Removing them keeps reviewers' attention on the live code.

**Important non-target — `livePanelBlur` and `livePanelFill`:** these widgets share the "Blur"/"Fill" naming convention but are **NOT inert**. They are toggled visible by [`applyVehicleDeployLiveTerminalChromeState`](../src/vehicles/deploy-timer-ui.ts#L853-L855) when the live terminal opens; they form the modal panel backdrop. Cleanup must surgically target the button-level widgets only. Confirmed by inspecting the only `safeSetUIWidgetVisible(*Blur, ...)` / `safeSetUIWidgetVisible(*Fill, ...)` call site that takes a non-`false` second argument: lines 854-855 only reference `cache.livePanelBlur` and `cache.livePanelFill`.

**Visual impact:** zero. Tier 1 widgets are never rendered today, so removing them is undetectable in-game. Tier 2 lines are runtime no-ops. Tier 3 is bytes only.

**Conversation history.** Identified 2026-05-04 during the precise button comparison work in [`conquest_vehicle_deploy_comparisons.md`](./conquest_vehicle_deploy_comparisons.md) §4.5. The v1.463 shadow removal was the precedent; same author-acknowledged "scaffolding from a planned visual style that didn't ship" lineage.

## Risks

1. **Did I miss a `safeSetUIWidgetVisible(*Blur|*Fill, true)` call site?** Mitigation: the audit covered every grep hit for `[Bb]lur|[Ff]ill` in the file; the only non-`false` second-arg site is `applyVehicleDeployLiveTerminalChromeState` at lines 854-855 (livePanel — out of scope). Risk: low. Validation: visual smoke in-game would expose any regression.

2. **Did I miss an external consumer of the cache fields?** Mitigation: project-wide grep for `spawnButtonBlur|spawnButtonFill|groundButtonBlur|groundButtonFill|closeButtonBlur|closeButtonFill` returned hits only in `deploy-timer-ui.ts` and `hud-cache-types.ts`. Risk: zero.

3. **Did I miss a code path that creates a `VehicleDeployTimerCheckbox*` widget elsewhere?** Mitigation: project-wide grep for each of the 7 names returned only the cleanup function and the v1.463 plan's audit table — no creation site exists. Risk: zero.

4. **Confusion between `livePanelBlur` and `*ButtonBlur`.** Mitigation: edits target specific cache field names (`spawnButtonBlur` etc.), not "all Blur/Fill widgets". The live panel helper is untouched. Validation: smoke test of the live terminal modal panel will visually expose any incorrect deletion.

5. **Stale per-pid cache fields after live reload** — same non-issue as v1.463: Portal does not preserve script state across reloads (reload = fresh map = fresh cache). Risk: zero.
