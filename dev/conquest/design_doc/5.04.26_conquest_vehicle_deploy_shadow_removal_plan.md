## Context

**What:** delete every text-shadow widget from the vehicle deploy timer HUD family. The shadow widgets currently sit *behind* their corresponding text widgets, offset a few pixels with `COLOR_DARK_BLACK` fill at reduced alpha, to give text a drop-shadow effect for legibility on the panel background.

**Why:** per-pid widget count reduction. Each row of the deploy HUD currently builds **18 widgets** when both action buttons are present (`spawnButton*` + `groundButton*` widget sets at 6 each, `playerPlate`/`playerText`/`playerShadow` at 3, `vehiclePlate`/`vehicleText`/`vehicleShadow` at 3). After removal: **14 widgets** per row. The panel-level close button drops from 6 → 5. Across 4 visible rows + close button: **~21 widgets/pid reclaimed** in the steady-state vehicle-deploy HUD.

**Visual impact:** white text on the dark blue/gray panel backgrounds becomes single-layer (no drop-shadow separation). The button gradient fills (`COLOR_GRAY_DARK` → `COLOR_BLUE` on hover) provide their own contrast against white text; user has accepted this tradeoff. **In-game verification required post-ship** — see Validation below.

**Conversation history.** Identified during the [`conquest_vehicle_deploy_comparisons.md`](./conquest_vehicle_deploy_comparisons.md) exercise (2026-05-04). User confirmed that BillDukes' equivalent UI ships with no text shadows on its 3-state buttons; Conquest's heavier visual chrome can drop them with no functional regression.

## Risks

1. **Visual legibility regression** — text without shadow may be marginally less readable on light parts of the gradient backgrounds. **Mitigation:** in-game verify per validation step. **Rollback:** trivial; revert the commit. **Non-mitigation:** if user accepts the look, no further work; if not, alternative paths (e.g. heavier opacity on the fill background) belong in a follow-up plan, not this one.

2. **Late-joiner widget count cache drift** — late-joiner cold-open path expects a specific widget count for the deploy HUD family during prebuild. **Mitigation:** the `hudWarmCompleted` gate doesn't count widgets; it observes which fields are set on `cache.root`. Removing shadow fields shrinks the structure but doesn't gate readiness. Verified by reading `isVehicleDeployTimerHudCacheUsable` and the `prebuildVehicleDeployTimerHudHidden*` path.

3. **Stale per-pid cache fields after live reload** — if a player connects mid-match and the prior version's cache had `closeButtonTextShadow` populated, the new code never reads it; the widget remains in scene. **Not applicable in practice:** Portal does not preserve script state across reloads (reload = fresh map = fresh script context = fresh cache). Confirmed by the project's `_PORTAL_RUNTIME_PERSISTENCE_NONE` assumption baked into `onPlayerLeaveGameImpl`. Risk score: 0.

4. **CheckboxMarkShadow line 263 dead code** — removing this also removes a defensive cleanup against a widget the live build does not produce. If a yet-undiscovered code path produces a widget by that name, deleting the cleanup leaks it. **Audit confirmed:** project-wide grep returns no creation site. Risk score: 0.
