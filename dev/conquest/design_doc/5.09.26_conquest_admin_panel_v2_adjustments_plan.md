# Plan: Admin Panel v2 Adjustments

**Date:** 2026-05-09
**Baseline:** v1.492 (admin panel re-enable + 3 diagnostic toggles shipped)
**Status:** Awaiting approval

## Context

v1.492 shipped the admin-pid scoped admin panel with three new diagnostic toggle buttons (Toggle Combat HUD / Toggle Vehicle Overlay / Toggle Spectator) per [`5.08.26_conquest_admin_panel_diagnostic_toggles_plan.md`](./5.08.26_conquest_admin_panel_diagnostic_toggles_plan.md). User SP-tested and gave 5 follow-up adjustments + 1 verification request. This plan addresses all of them in a single bump.

## Verification (no code change — just codifying expected behavior)

All three diagnostic toggles affect **every player on the server**, not just the admin:

| Toggle | Scope | State field |
|---|---|---|
| Toggle Combat HUD | Global — every player's combat HUD hidden | `State.conquest.debug.hudModeOverride` |
| Toggle Vehicle Overlay | Global — every player's vehicle deploy timer panel hidden | `State.conquest.debug.vehicleDeployTimerDisabledByAdmin` |
| Toggle Spectator | Global — every player's SPECTATE button greyed/relabeled + active spectator kicked | `State.conquest.debug.spectatorDisabledByAdmin` |
| **Toggle Position Debug** | **Admin only** — only admin's HUD shows the overlay | per-pid via `state.posDebugVisible` |

This is already correct in the v1.492 implementation; no change needed. Codified here as a comment block in the relevant files for future reference.

## Five adjustments

### Adjustment 1 — Move dynamic spectator label from admin button to player-facing SPECTATE button

**Problem:** v1.492 made the **admin's** "Toggle Spectator" button label dynamic (reads `Spectator Disabled` when off). User wants:
- Admin's panel button = **static** "Toggle Spectator" always.
- Player-facing SPECTATE buttons (the small player-ready-panel + admin's full ready dialog roster) = **dynamic** label that reads `Spectator Disabled` when admin has disabled spectator. Already goes disabled-grey via `applyCoachButtonState`; user wants the LABEL swap on top of that.

**Layout note (per user):** "Spectator Disabled" is longer than "SPECTATE" — the button text will wrap to two lines. Confirm the button's height/wrap layout supports two-line text without truncation.

**Files to modify:**
- [`spectator/coach-button-sync.ts`](../src/spectator/coach-button-sync.ts) — extend `applyCoachButtonState` with a label-text override based on `State.conquest.debug.spectatorDisabledByAdmin`. The function already accepts the label widget as a parameter (line 43-61), so no widget-ID lookup change needed.
- [`admin-panel/build.ts`](../src/admin-panel/build.ts) — change the "Toggle Spectator" button's label from `getSpectatorToggleLabelKey()` (dynamic) to a static `mod.stringkeys.twl.adminPanel.actions.spectatorToggle`.
- [`admin-panel/build.ts`](../src/admin-panel/build.ts) — DELETE the `getSpectatorToggleLabelKey` and `syncSpectatorToggleLabelForPid` helpers added in v1.492.
- [`admin-panel/events.ts`](../src/admin-panel/events.ts) — REMOVE the `syncSpectatorToggleLabelForPid(playerId)` call inside the toggle handler. Keep the rest of the handler (state flip, kick, refresh broadcast).
- [`conquest-flow.ts`](../src/conquest-flow.ts) — REMOVE the `syncSpectatorToggleLabelForPid(adminPid)` call in `resetDiagnosticToggleFlags`. Keep the flag reset.
- After the spectator-flag flip, the existing `refreshAllVisiblePlayerReadyPanels()` + `renderReadyDialogForAllVisibleViewers()` broadcast (already in the toggle handler) re-renders every viewer's COACH/SPECTATE button — that's the entry point where the label swap will land.

**Verification:** SP test — admin presses Toggle Spectator → player ready panel + admin dialog SPECTATE buttons all show `Spectator Disabled` in grey. Press again → buttons restore `SPECTATE` label and re-enable.

**Verify wrap:** open admin's full ready dialog with spectator disabled — admin's own SPECTATE button shows two-line "Spectator\nDisabled". If button height truncates the second line, increase the button height in the layout const.

### Adjustment 2 — Toggle Combat HUD pre-game expectation

**Investigation outcome:** the `Toggle Combat HUD` button only flips `hudModeOverride` which gates the combat HUD core (tickets / flags / engage). It does **not** gate the top-HUD shell (branding, clock, ready-count, status text, help text). Pre-game, the combat HUD core is already hidden because there's nothing live to render — so pressing the button pre-game has **no visible effect**. This is correct behavior, not a bug.

**Per user direction:** "While the playable area isn't really accessible, the top HUD is definitely visible pregame. We do not want to hide the clock."

**Action:** No functional change. Add a one-line comment to the toggle handler so the next reader (and the user re-reading this in three weeks) knows pre-game silence is intentional.

**Files:**
- [`admin-panel/events.ts`](../src/admin-panel/events.ts) — add comment above the `combatHudToggle` block: "Pre-game no-op: this toggles only the live-match combat HUD (tickets/flags/engage). The top-HUD shell (clock/branding/status) is owned by `top-hud-shell.ts` and stays visible regardless of this flag — by design (user 2026-05-09)."

### Adjustment 4 — Remove the existing `Toggle Deploy Timers Visible While Deployed` button

**Investigation outcome:** the existing button is **NOT** duplicate functionality — it's per-pid and slightly different:
- **Existing per-pid `vehicleTimersVisibleWhileDeployed`** (`admin-panel/events.ts:127-141`): when toggled ON for the admin's pid, *that admin's* vehicle deploy timer HUD shows ALL vehicle slots (including occupied ones) even while they're deployed. When OFF (default), the panel filters to only idle slots. Per-admin viewer detail.
- **New global `vehicleDeployTimerDisabledByAdmin`** (v1.492): server-wide force-hide of the entire vehicle deploy timer panel for all players. Skips the entire render-plan compute.

These are orthogonal but overlap in user mental model. Per user direction: disable the old button.

### Adjustment 5 — Rename `Ground Deploy All` → `Force Spawn Vehicles (Vanilla Only)`

**Investigation outcome:** `forceSpawnAllReadyVehicleSlots()` calls `applySpawnerEnablementForMatchup(matchupIndex, true)` which only auto-spawns in **Vanilla Deploy mode**. In HQ Deploy mode (the more common Conquest mode), it enables slots but doesn't dispatch — players have to request individual spawns. So the button has functional effect in Vanilla mode and is silent in HQ Deploy mode.

**Per user direction:** keep the function as-is, just rename the button to clarify its scope.

**Files:**
- [`strings.json`](../src/strings.json) — rename:
  - `actions.groundDeployAll`: `"Ground Deploy All"` → `"Force Spawn Vehicles (Vanilla Only)"`
  - `tester.buttons.groundDeployAll`: `"Ground Deploy All"` → `"Force Spawn Vehicles (Vanilla Only)"`
- **Player-facing string change — pre-approved by user in this plan.**
