## Context

Per the Naming Economy section of [`conquest_optimization_state.md`](./conquest_optimization_state.md) and Tier F1 of [`conquest_optimization_analysis.md`](./conquest_optimization_analysis.md), the codebase carries a `conquestPhase[2A|2B|3|4|4B]` prefix on **104 functions** that names *when* the function was implemented (e.g., during Phase 2A capture-bring-up), not *what* it does. This is an anti-pattern called out in the design rulebook's naming standard ("name for what, not when or why"). Renames are expected to:

- Reclaim ~4–6 KB of bundle bytes (modest at our 176 KB headroom — bundle isn't the binding constraint).
- Reclaim ~1–2 KB of runtime heap via interned-string deduplication.
- Substantially improve PR review readability by removing the verbose phase prefix from every call site.

This wave is **F1 only**. The previously-noted UI.COLORS cherry-pick does *not* fit naturally with F1 — F1's affected files (`index/capture-tickets.ts`, `index/capture-sound.ts`, `index/capture-vo.ts`, `state/spawn-charge.ts`) have very few `mod.CreateVector(r, g, b)` call sites. UI.COLORS is deferred to Wave 5 (per-element minimization) where UI files are touched.

## Disambiguation strategy for the 7 collisions

**Decision: module-prefixed disambiguation.** Phase 4 functions live in `capture-sound.ts` (sound subsystem), Phase 4B in `capture-vo.ts` (voice-over subsystem). Each colliding twin gets a module-domain prefix: `captureSound*` for Phase 4, `captureVo*` for Phase 4B.

For event-hook functions, prepend the module prefix:
- `conquestPhase4OnMatchLiveStart` → `captureSoundOnMatchLiveStart`
- `conquestPhase4BOnMatchLiveStart` → `captureVoOnMatchLiveStart`
- `conquestPhase4OnNotLiveReset` → `captureSoundOnNotLiveReset`
- `conquestPhase4BOnNotLiveReset` → `captureVoOnNotLiveReset`
- `conquestPhase4OnPlayerLeaveOrResetPid` → `captureSoundOnPlayerLeaveOrResetPid`
- `conquestPhase4BOnPlayerLeaveOrResetPid` → `captureVoOnPlayerLeaveOrResetPid`
- `conquestPhase4OnCapturePointStateSample` → `captureSoundOnCapturePointStateSample`
- `conquestPhase4BOnCapturePointStateSample` → `captureVoOnCapturePointStateSample`

For internal helpers, weave the module token into the name where it reads naturally:
- `conquestPhase4ResetQueueAndThrottleState` → `resetCaptureSoundQueueState`
- `conquestPhase4BResetQueueAndThrottleState` → `resetCaptureVoQueueState`
- `conquestPhase4GetRecipientThrottleKey` → `getCaptureSoundRecipientThrottleKey`
- `conquestPhase4BGetRecipientThrottleKey` → `getCaptureVoRecipientThrottleKey`
- `conquestPhase4GetRecipientsForEvent` → `getCaptureSoundRecipientsForEvent`
- `conquestPhase4BGetRecipientsForEvent` → `getCaptureVoRecipientsForEvent`

Net effect: collision-free, names tell you which subsystem owns the behavior, average length still drops vs. the original `conquestPhaseN[A-D]` prefix.

## Why this is safe (rename-pass-specific risk notes)

- **Pure rename, no semantic change.** Function bodies and call signatures unchanged. Behavior is identical post-rename.
- **TypeScript catches missed call sites.** The codebase is `// @ts-nocheck` at file headers but the bundler typechecks via `tsc --noEmit` per the bumpVersion verification step. Any unrenamed call site to a renamed function compiles to an undefined reference and fails typecheck.
- **No runtime metaprogramming.** No `eval`, no dynamic `Function` constructor, no string-based function lookup that could escape the typechecker. All call sites are static identifiers.
- **No breaking changes to external API.** The Portal event-handler exports in `src/index.ts` are not phase-prefixed; they remain unchanged. No external surface is affected.
- **Disambiguation is conservative.** The 7 collision twins get the longest disambiguated names — preserves complete clarity over byte savings.
- **Doc updates lag code by one batch.** The rename happens first; doc sweeps catch up. Risk: AGENTS.md temporarily references an old function name. Mitigation: include AGENTS.md update in the same commit/version as the code rename for `markHudDirty` (the only function whose name is referenced in a binding architectural contract).
