# Plan: Re-enable Admin Panel + Position Debug (admin-pid scoped) + Three Diagnostic Toggle Buttons

**Date:** 2026-05-08
**Baseline:** v1.491
**Status:** Approved — ready to implement

## Context

The v1.491 8–10 player MP playtest crashed with `Mod has been running for 1,716ms this frame which exceeds max evaluation time of 1,000ms` — a single-frame CPU breach, not a heap leak. Investigation in [`conquest_optimization_state.md`](./conquest_optimization_state.md) "Per-frame CPU fan-out" + new Tier S in [`conquest_optimization_analysis.md`](./conquest_optimization_analysis.md) identified the most likely cause as **forced N-player broadcasts converging on a single frame** — particularly `updateConquestCombatHudForAllPlayers(force=true)` from `OnPlayerEnter/ExitCapturePoint` (S1/S2) and `updateVehicleDeployTimerHudForAllPlayers()` from vehicle events (S3).

The user wants **diagnostic toggle buttons** that hide these UIs server-wide so a follow-up MP playtest can bisect which surface is the dominant contributor. The buttons live on the admin panel — which is currently feature-flagged off.

Re-enabling `FEATURE_ADMIN_PANEL` would itself add another N-player broadcast pattern (`updateAdminPanelActionCountForAllPlayers` fires on every admin click) on top of the v1.491 issue. Solution: scope everything admin-pid-only — only the claimed admin builds + sees the panel, only the admin's HUD shows the action counter, only the admin can use position debug. This collapses the N-player broadcast to a single-pid update and unblocks both the diagnostic capability and the eventual map-dev tooling without compounding the spike.

`FEATURE_POSITION_DEBUG` is also re-enabled but only for the admin pid — separate from the v1.491 debugging work, used for vehicle/spawn position tuning during map development. **Position debug starts DISABLED**; admin must explicitly press the existing `Toggle Position Debug` button to bring up the overlay (no auto-start on deploy). This avoids polluting normal-play sessions with the overlay.

In addition, a third diagnostic toggle is added for the spectator subsystem itself: **"Toggle Spectator"** lets the admin disable spectator-mode availability server-wide so a follow-up MP playtest can confirm whether the spectator system contributes to the v1.491 spike. Spectator is **enabled** at match start by default; admin can flip it. Button label is dynamic — reads `Toggle Spectator` when enabled, `Spectator Disabled` when disabled — so the admin sees the current state at a glance.

## Bundle / heap / CPU budget impact

| Budget | Headroom now | After re-enable | Verdict |
|---|---:|---:|---|
| Bundle bytes (1 MiB) | 163 KB free | ~113 KB free (~10.7%) | ✅ comfortable |

## Goals

1. **Re-enable `FEATURE_ADMIN_PANEL`** but only build + show + dispatch for the claimed admin pid.
2. **Re-enable `FEATURE_POSITION_DEBUG`** scoped to admin only — manual-toggle only (no auto-start on deploy).
3. **Add three new diagnostic admin buttons:**
   - **"Toggle Combat HUD"** (label static) — toggle global `State.conquest.debug.hudModeOverride = "off"`/`"core"`. Uses existing pipeline early-return at [`pipeline.ts:106-115`](../src/ui/conquest/hud-core/pipeline.ts#L106-L115); short-circuits all per-player VM-build work.
   - **"Toggle Vehicle Overlay"** (label static) — toggle new global `State.conquest.debug.vehicleDeployTimerDisabledByAdmin: boolean`. Add early-return at the top of `refreshVehicleDeployTimersForPlayerPreservingVisibility` so the per-pid render-plan compute is skipped (currently it runs even when hidden).
   - **"Toggle Spectator"** (label dynamic — reads `Spectator Disabled` when off) — toggle new global `State.conquest.debug.spectatorDisabledByAdmin: boolean`. Default `false` (enabled). Gates spectator availability via `isSpectatorAvailableForActiveMap` / `isCoachButtonEnabledForPid`. If a player is currently in the spectator slot when admin disables, call `exitSpectatorMode` cleanly so they redeploy on foot.
4. **Admin handoff cleanup:** when admin A gives up / disconnects and admin B claims, A's panel + counter + position-debug overlay must tear down; B's must build.

## Implementation Order

### Phase 1 — Re-enable position debug with admin-pid scope, manual-toggle only (lowest risk, smallest diff)

1. `config/conquest-constants.ts` — flip `FEATURE_POSITION_DEBUG = true`.
2. `index.ts` — uncomment the `import './hud/position-debug';` line (line 44 is currently commented `// @feature FEATURE_POSITION_DEBUG`). Prebuild script already handles this via `// @feature` markers.
3. **No auto-start.** Per user direction, position debug starts disabled — admin must press `Toggle Position Debug` in the admin panel to bring it up. Approach: replace the body of `autoStartPositionDebugOnDeploy` ([`hud/position-debug.ts:342-353`](../src/hud/position-debug.ts#L342-L353)) with an early-return so the reveal path no longer enables it. The function stays in place for callers; it just becomes a no-op. The existing `Toggle Position Debug` admin button (already in `admin-panel/events.ts`) is the only enable path.
4. **Admin handoff teardown:** add a new exported helper `tearDownPositionDebugForPid(pid)` in `hud/position-debug.ts` that flips `posDebugVisible = false` + `posDebugToken++` (cancels the loop) + sets all overlay widgets invisible. Call it from new chokepoint `Admin.onAdminPidChanged(prevPid, nextPid)` (see Phase 2). This ensures admin A's overlay stops looping after they lose admin status.
5. **No bring-up on handoff.** Since auto-start is removed, the new admin starts with no overlay. They press the toggle button when they want it.

### Phase 2 — Re-enable admin panel with admin-pid scope

1. `config/conquest-constants.ts` — flip `FEATURE_ADMIN_PANEL = true`.
2. `index.ts` — uncomment the 4 `// @feature FEATURE_ADMIN_PANEL` import lines.
3. **Build path gates** — gate the 4 `ensureAdminPanelWidgets` call sites on `Admin.isAdmin(pid)`. Files:
   - [`ready-dialog/dialog-build.ts:16,48,69`](../src/ready-dialog/dialog-build.ts#L16)
   - [`ready-dialog/dialog-build-sections.ts:232`](../src/ready-dialog/dialog-build-sections.ts#L232)
   - [`ready-dialog/lifecycle.ts:60,115`](../src/ready-dialog/lifecycle.ts#L60)
4. **Counter widget gate** — at [`ui/conquest/top-hud-shell.ts:200,220`](../src/ui/conquest/top-hud-shell.ts#L200), wrap `buildConquestAdminActionCounterWidget(player, pid, refs)` calls with `if (FEATURE_ADMIN_PANEL && Admin.isAdmin(pid))`.
5. **Counter broadcast gate** — at [`hud/update-helpers.ts:6-12`](../src/hud/update-helpers.ts#L6-L12), replace `updateAdminPanelActionCountForAllPlayers` body with single-pid update against the current admin pid. Eliminates the N-player broadcast.
6. **Admin handoff state machine:** add a single chokepoint helper `Admin.onAdminPidChanged(prevPid: number | undefined, nextPid: number | undefined)` in `admin/identity.ts` and call it inside `claimAdmin` + `giveUpAdmin` + `onPlayerLeave` after the slot mutates. The helper:
   - If `prevPid !== undefined`: tear down their admin panel UI (set `adminPanelVisible = false`, `adminPanelBuilt = false`, hide widgets via existing `setAdminPanelChildWidgetsVisible(prevPid, false)`); tear down their counter widget; tear down their position debug overlay (Phase 1).
   - If `nextPid !== undefined`: ensure widgets build on the new admin's next dialog open (current lazy-build path handles this, just don't preempt). No position-debug bring-up since manual-toggle only.
7. **Action counter dependency:** the action-counter widget lives inside `topHudShell` which is per-pid. On admin handoff, the prev admin's `topHudShell` retains the counter widget but invisible. New admin's `topHudShell` may need its counter widget built lazily — extend the existing `top-hud-shell.ts` ensure path to include the counter when admin changes (or rebuild the new admin's shell once via existing destroy + lazy-build dispatch).

   - `UI_TEST_BUTTON_VEHICLE_OVERLAY_TOGGLE_ID`
   - `UI_TEST_BUTTON_SPECTATOR_TOGGLE_ID`
6. **Build the buttons.** In [`admin-panel/build.ts`](../src/admin-panel/build.ts), append three `addTesterActionButton(...)` calls in the row layout.
7. **Dynamic label refresher for spectator button.** Add a helper `refreshSpectatorToggleButtonLabel(playerId)` (in `admin-panel/visibility.ts` or a new file `admin-panel/dynamic-labels.ts`):
   ```ts
   function refreshSpectatorToggleButtonLabel(playerId: number): void {
     const labelWidget = safeFind(UI_TEST_BUTTON_SPECTATOR_TOGGLE_ID + playerId + "_LABEL");
     if (!labelWidget) return;
     const stringKey = State.conquest.debug.spectatorDisabledByAdmin
       ? mod.stringkeys.twl.adminPanel.actions.spectatorToggleDisabled
       : mod.stringkeys.twl.adminPanel.actions.spectatorToggle;
     safeSetUITextLabel(labelWidget, msg(stringKey));
   }
   ```
   Call it from: (a) the build path (after the button is added) so the initial label reflects current flag, (b) the toggle handler in step 8 after the flag flips. The widget id suffix `_LABEL` follows the project's existing `UI_*_BUTTON_*_LABEL_ID` pattern — confirm the actual suffix at implementation time by reading neighboring tester buttons.
8. **Wire the actions.** In [`admin-panel/events.ts`](../src/admin-panel/events.ts) inside `tryHandleAdminTesterButtonEvent`, add three `tryHandleAdminPanelPrimaryAction` blocks:
   ```ts
   // Toggle Combat HUD
   if (widgetName === UI_TEST_BUTTON_HUD_TOGGLE_ID + playerId) {
     if (!tryConsumeUIButtonPrimaryClickEvent(...)) return undefined;
     const next = getConquestHudMode() === "core" ? "off" : "core";
     setConquestHudMode(next);
     if (next === "core") markHudDirty();
     handleAdminPanelAction(eventPlayer, mod.stringkeys.twl.adminPanel.actions.combatHudToggle);
     return true;
   }
   // Toggle Vehicle Overlay
   if (widgetName === UI_TEST_BUTTON_VEHICLE_OVERLAY_TOGGLE_ID + playerId) {
     if (!tryConsumeUIButtonPrimaryClickEvent(...)) return undefined;
     State.conquest.debug.vehicleDeployTimerDisabledByAdmin = !State.conquest.debug.vehicleDeployTimerDisabledByAdmin;
     updateVehicleDeployTimerHudForAllPlayers();
     handleAdminPanelAction(eventPlayer, mod.stringkeys.twl.adminPanel.actions.vehicleOverlayToggle);
     return true;
   }
   // Toggle Spectator
   if (widgetName === UI_TEST_BUTTON_SPECTATOR_TOGGLE_ID + playerId) {
     if (!tryConsumeUIButtonPrimaryClickEvent(...)) return undefined;
     const wasDisabled = State.conquest.debug.spectatorDisabledByAdmin;
     State.conquest.debug.spectatorDisabledByAdmin = !wasDisabled;
     // If we're transitioning ENABLED -> DISABLED and there's an active spectator, kick them out
     // cleanly so they redeploy on foot. exitSpectatorMode is idempotent.
     if (!wasDisabled) {
       const specPid = State.players.spectatorPid;
       if (specPid !== null) {
         const specPlayer = safeFindPlayer(specPid);
         if (specPlayer) exitSpectatorMode(specPlayer, specPid);
       }
     }
     // Re-render every viewer's COACH button (existing fan-out helpers handle this).
     refreshAllVisiblePlayerReadyPanels();
     renderReadyDialogForAllVisibleViewers();
     // Refresh the spectator-toggle button's own label to reflect the new state.
     refreshSpectatorToggleButtonLabel(playerId);
     // Audit log uses the *current* state's string key so the log line is accurate.
     const labelKey = State.conquest.debug.spectatorDisabledByAdmin
       ? mod.stringkeys.twl.adminPanel.actions.spectatorToggleDisabled
       : mod.stringkeys.twl.adminPanel.actions.spectatorToggle;
     handleAdminPanelAction(eventPlayer, labelKey);
     return true;
   }
   ```
9. **Visibility wiring.** Add the three new widget IDs to `setAdminPanelChildWidgetsVisible` ID array in `admin-panel/visibility.ts` so the show/hide cascade includes them.
10. **Lifecycle reset.** On match-end / fresh-setup, reset all three diagnostic flags (`hudModeOverride = "core"`, `vehicleDeployTimerDisabledByAdmin = false`, `spectatorDisabledByAdmin = false`) so a new match starts with all UIs visible and spectator available (avoid sticky off-state across matches). Add to existing `endMatch` / `triggerFreshMatchSetup` paths in `conquest-flow.ts`. After the flag reset, call `refreshSpectatorToggleButtonLabel(adminPid)` if there's a current admin so their button label is in sync.

## Verification

### SP smoke (mandatory before MP)

1. **Position debug — no auto-start, manual only** — boot SP, claim admin, deploy → NO overlay shown. Open admin panel → press `Toggle Position Debug` → overlay appears. Press again → overlay disappears.
2. **Admin panel admin-only** — boot SP without claiming admin → admin panel does NOT build (open ready dialog: no admin section, no top-right toggle). Claim admin → admin panel widgets build on next dialog open; all action buttons work.
3. **Action counter on admin only** — top of HUD: counter widget present on admin's HUD only. Click any admin action → counter increments; non-admin players (in MP test later) see no counter.
4. **"Toggle Combat HUD" button** — click while live → entire combat HUD (tickets / flags / engage) hides for ALL players within ~200ms (next throttled tick); world-log shows "{name} pressed Toggle Combat HUD". Click again → HUD restores. Verify the off mode actually short-circuits the per-frame compute (engage/popout state stops moving).
5. **"Toggle Vehicle Overlay" button** — click → vehicle deploy timer panel hides for ALL players; click again → restores. While disabled, no engine error or HUD flicker.
6. **"Toggle Spectator" button — basic toggle** — pre-LIVE, no spectator: click → SPECTATE button on every viewer's panel goes disabled-grey; admin's button label changes to `Spectator Disabled`. World-log shows audit line. Click again → SPECTATE button re-enables; admin's label returns to `Toggle Spectator`.
7. **"Toggle Spectator" button — kicks active spectator** — pre-LIVE: player A clicks SPECTATE → claims slot. Admin clicks `Toggle Spectator` (disable) → A is cleanly exited (spectator-action's `exitSpectatorMode` fires; A redeploys on foot). Verify hide-room geometry tears down, free-cam loop terminates, A goes to deploy screen.
8. **Admin handoff** — admin A gives up → A's panel + counter tear down cleanly (no orphan widgets); A's position-debug overlay tears down if active. B claims → B's panel builds on next dialog open; counter widget appears on B's HUD only; B starts with no position-debug overlay (manual-toggle as in test 1).
9. **Match-end reset** — end match while any of the three diagnostic toggles is off → next match starts with all three at default (HUD on, vehicle overlay on, spectator enabled). Spectator button label resets to `Toggle Spectator`.

### MP playtest — diagnostic protocol for v1.491 spike

Run an 8–10p MP playtest with active LIVE play (capture-firefight clusters). Sequence:

| Step | State | Expected | Actual |
|------|---|---|---|
| 0 | All three ON (baseline) | Hit ~1,716ms spike or eval-cap crash within 5–15 min of LIVE | _record time-to-spike_ |
| 1 | Vehicle Overlay OFF only | Reduce or eliminate spike? | _record_ |
| 2 | Combat HUD OFF only | Reduce or eliminate spike? | _record_ |

## Risks

| # | Risk | Likelihood | Mitigation |
|---|---|:---:|---|
| R1 | Admin handoff state machine misses an edge case (panel widgets leak, counter widget orphan, position-debug loop runs on stale token) | Medium | Single chokepoint `onAdminPidChanged` is the only mutator; called from all 3 admin slot transitions (claim/give-up/disconnect). Test 8 in SP smoke covers this. |
| R2 | Diagnostic toggle off-state persists across match-end (sticky flag) → next match starts with HUD off, confusing | Low | Phase 3 step 10 explicitly resets all three flags on `endMatch` + `triggerFreshMatchSetup`. |
| R3 | Vehicle overlay short-circuit hides cache-rebuild path → re-enable shows stale data | Low | The early-return only sets visibility false; it does NOT delete cache state. Re-enable just lets the normal refresh path run, which already handles cold-cache rebuild. |
| R4 | Combat HUD off mode leaves engage panel state stale → re-enable shows wrong flag-engage state | Low | Existing `markHudDirty()` in re-enable path forces full re-render on next throttled tick. Pattern is already battle-tested by other off-mode users. |
| R5 | Counter widget single-pid update misses edge case where admin pid changes mid-action | Low | The new helper `updateAdminPanelActionCountForAdmin()` reads `Admin.getCurrentAdminPid()` fresh each call. If admin transitions during an action, the post-transition admin gets the count update, which is acceptable. |
| R6 | Re-enabling `FEATURE_ADMIN_PANEL` adds a new attack surface for the v1.491 issue itself | Low (mitigated) | Admin-pid scope eliminates the only N-player broadcast `FEATURE_ADMIN_PANEL` introduced. Net effect on per-frame budget is essentially zero. Phase 4 verification confirms via MP playtest. |
| R7 | Spectator-toggle disable while a spectator is mid-claim transition (entering the slot at the same tick admin disables) | Very Low | The toggle handler reads `State.players.spectatorPid` after the flag flip; `exitSpectatorMode` is idempotent (it bails if the slot doesn't match). Worst case: claim handler may complete after the disable, leaving the player briefly in spec until the next refresh. The `exitSpectatorMode` call covers this with the `if (State.players.spectatorPid !== pid) return` guard. |
| R8 | Dynamic spectator button label diverges from actual flag state | Low | Single-source-of-truth: every flag flip is followed by `refreshSpectatorToggleButtonLabel(adminPid)`. Match-end reset path also calls it. The label widget's id is the existing tester-button label suffix; no new widget plumbing. |
| R9 | Removing position-debug auto-start may break some existing reveal-path assumption (some caller relied on overlay auto-coming-up) | Very Low | The overlay was admin-only-by-default before this change too (just gated by feature flag); removing auto-start has no production effect. Admin reveal/respawn paths that previously called `autoStartPositionDebugOnDeploy` now no-op cleanly. |
