## Design

### Mode state

Add to module-local state in [`spectator-action.ts`](../src/spectator/spectator-action.ts):

```ts
type SpectatorTrackingMode = "free" | "focusing" | "in_focus" | "defocusing";
let _spectatorTrackingMode: SpectatorTrackingMode = "free";
let _spectatorTrackingTargetPid: number | null = null;
let _spectatorTrackingLastJumpEdge: boolean = false; // edge-detection memo for Jump press
```

Single-spectator slot → module-local is sufficient; no per-pid record. State is reset to `free` / `null` / `false` in:
- `enterSpectatorMode` (defensive — fresh claim should always start in free-fly)
- `exitSpectatorMode` (cleanup before deploy-screen transition)
- `onSpectatorMatchEnd`, `onSpectatorFreshSetup`, `onSpectatorPlayerLeave` (lifecycle deallocators)

### Jump-press edge detection (mode trigger)

Inside `runSpectatorFreeCameraLoop`, add at the top of each tick:

```ts
const isJumping = safeGetSoldierStateBool(eventPlayer, mod.SoldierStateBool.IsJumping, false);
const jumpRisingEdge = isJumping && !_spectatorTrackingLastJumpEdge;
_spectatorTrackingLastJumpEdge = isJumping;

if (jumpRisingEdge) {
    if (_spectatorTrackingMode === "free") {
        const nextPid = findNextSpectatorTrackingTarget(null, pid);
        if (nextPid !== null) {
            _spectatorTrackingTargetPid = nextPid;
            _spectatorTrackingMode = "focusing"; // start lerp toward target
        }
    } else {
        const nextPid = findNextSpectatorTrackingTarget(_spectatorTrackingTargetPid, pid);
        if (nextPid !== null) {
            _spectatorTrackingTargetPid = nextPid;
            // Stay in current mode (keep camera following; it'll lerp to the new target's pos).
        }
    }
}
```

PCT pattern: hold Jump = no extra cycle (only the rising edge counts).

### WASD-exit detection

After the Jump-press handler, before the existing free-fly velocity decomposition:

```ts
if (_spectatorTrackingMode !== "free") {
    // Check for any horizontal movement intent. velX/velZ already read; reuse.
    const hasMoveInput = Math.abs(velX) > 0.05 || Math.abs(velZ) > 0.05;
    if (hasMoveInput) {
        _spectatorTrackingMode = "defocusing";
        _spectatorTrackingTargetPid = null;
    }
}
```

PCT exits via velocity-projection threshold; the small floor (0.05 in our units) absorbs joystick-deadzone noise on controllers.

### Per-tick branch

After the input reads, branch on `_spectatorTrackingMode`:

- `"free"` → existing free-fly position/rotation math (unchanged).
- `"focusing"` or `"in_focus"` → compute follow-cam target pose; lerp to it. Once `distance(cam, target_pos) < focusArriveDistance` and we were `focusing`, transition to `in_focus`.
- `"defocusing"` → lerp from current cam pose toward... what? PCT uses the pre-tracking free-fly state. Simpler: do nothing special — once `_spectatorTrackingMode = "defocusing"`, immediately set it to `"free"` and let the free-fly math take over. The smoothed `smoothedYaw`/`smoothedPitch` state from earlier ticks provides natural lerp continuity. Skip the substate; just snap-back to free-fly math with smoothing already active.

(Net: only 2 substates needed — `"free"` and `"in_focus"`. Drop `"focusing"` and `"defocusing"` from the type. Keeps code simple and matches the user's "basic" requirement; PCT's three-substate machine adds polish that we can always add later.)

**Simplified state:**
```ts
type SpectatorTrackingMode = "free" | "in_focus";
```

### Follow-cam math

```ts
const SPECTATOR_TRACK_BACK_DISTANCE = 3.0;       // PCT focusPullbackDistance
const SPECTATOR_TRACK_HEIGHT_OFFSET = 0.9;       // PCT focusHeightOffset
const SPECTATOR_TRACK_PITCH_OFFSET_RAD = 10 * (Math.PI / 180); // PCT trackedPlayerPitchOffsetRad
const SPECTATOR_TRACK_ROT_SMOOTHING = 0.12;      // PCT trackedRotationSmoothingYaw/Pitch
const SPECTATOR_TRACK_Y_SMOOTHING = 0.08;        // PCT trackedPlayerYSmoothing (terrain-bump damping)

// Inside the "in_focus" branch:
const targetPlayer = safeFindPlayer(_spectatorTrackingTargetPid);
if (!isValidPlayer(targetPlayer) || !isPlayerDeployed(targetPlayer)) {
    // Target invalidated mid-loop: freeze at last cam pose (PCT pattern).
    // Next Jump press will FindNext past this stale pid.
    // No mode transition; spec stays in_focus on the dead pid until they press Jump.
    continue;
}

const targetEyePos = mod.GetEyePosition(targetPlayer); // PCT uses GetEyePosition
const targetFacing = safeGetSoldierStateVector(targetPlayer, mod.SoldierStateVector.GetFacingDirection);
if (!targetFacing) continue;

// Flat (XZ) facing direction.
const tfX = mod.XComponentOf(targetFacing);
const tfZ = mod.ZComponentOf(targetFacing);
const tfFlatLen = Math.sqrt(tfX * tfX + tfZ * tfZ);
if (tfFlatLen <= 0.0001) continue;
const tFwdX = tfX / tfFlatLen;
const tFwdZ = tfZ / tfFlatLen;

// Target cam pos: 3m behind target's flat facing, +0.9m height.
const targetCamX = mod.XComponentOf(targetEyePos) - tFwdX * SPECTATOR_TRACK_BACK_DISTANCE;
const targetCamY = mod.YComponentOf(targetEyePos) + SPECTATOR_TRACK_HEIGHT_OFFSET;
const targetCamZ = mod.ZComponentOf(targetEyePos) - tFwdZ * SPECTATOR_TRACK_BACK_DISTANCE;

// Lerp position. Y smoothed separately (slower) to reduce terrain-bump jitter per PCT.
camX = spectatorFreeCamLerp(camX, targetCamX, SPECTATOR_TRACK_ROT_SMOOTHING);
camY = spectatorFreeCamLerp(camY, targetCamY, SPECTATOR_TRACK_Y_SMOOTHING);
camZ = spectatorFreeCamLerp(camZ, targetCamZ, SPECTATOR_TRACK_ROT_SMOOTHING);

// Yaw locked to target's flat facing yaw. Pitch +10° upward bias.
const targetYaw = Math.atan2(tFwdX, tFwdZ);
const targetPitch = -SPECTATOR_TRACK_PITCH_OFFSET_RAD; // negated to match the v1.483 engine convention fix
smoothedYaw = smoothedYaw === null ? targetYaw : spectatorFreeCamLerpAngle(smoothedYaw, targetYaw, SPECTATOR_TRACK_ROT_SMOOTHING);
smoothedPitch = smoothedPitch === null ? targetPitch : spectatorFreeCamLerp(smoothedPitch, targetPitch, SPECTATOR_TRACK_ROT_SMOOTHING);

// Apply transform (existing pattern).
mod.SetObjectTransform(camera, mod.CreateTransform(
    mod.CreateVector(camX, camY, camZ),
    mod.CreateVector(smoothedPitch, smoothedYaw, 0),
));
```

The negated pitch matches the existing `-Math.asin(...)` convention from v1.483 — engine `SetObjectTransform` interprets positive pitch as "look down", so a +10° upward bias is sent as `-DegToRad(10)`.

### Target cycling helper

```ts
// PCT's FindNextTarget pattern. Modulo-wraps. Skips spec pid + invalid + undeployed.
// `currentTargetPid === null` means "no current target yet — pick the first valid one."
function findNextSpectatorTrackingTarget(currentTargetPid: number | null, specPid: number): number | null {
    const all = mod.AllPlayers();
    const total = mod.CountOf(all);
    if (total === 0) return null;

    // Build a pid-ordered array for stable cycling. PCT iterates the engine's array directly;
    // we do the same — sort order is whatever mod.AllPlayers() returns.
    const candidatePids: number[] = [];
    for (let i = 0; i < total; i++) {
        const p = mod.ValueInArray(all, i) as mod.Player;
        if (!isValidPlayer(p)) continue;
        const candidatePid = safeGetPlayerId(p);
        if (candidatePid === undefined) continue;
        if (candidatePid === specPid) continue; // skip spec themselves
        if (!isPlayerDeployed(p)) continue;     // alive + deployed only
        candidatePids.push(candidatePid);
    }
    if (candidatePids.length === 0) return null;

    if (currentTargetPid === null) return candidatePids[0];

    const idx = candidatePids.indexOf(currentTargetPid);
    if (idx < 0) return candidatePids[0]; // current target is invalid; restart from index 0
    return candidatePids[(idx + 1) % candidatePids.length]; // wrap
}
```

## Edge Cases

| Case | Behavior |
|---|---|
| Press Jump from free-fly with **no other deployed players** | `findNextSpectatorTrackingTarget` returns `null`. Mode stays `"free"`. Spec keeps free-flying. (Camera doesn't lurch; Jump just behaves as +Y vertical lift like before.) |
| Tracked player **dies** mid-tick | `isPlayerDeployed` flips to false → tick `continue`s without applying transform → camera freezes at last pose (PCT pattern). Spec presses Jump → `findNextSpectatorTrackingTarget` finds the next valid pid; if dead pid is no longer in the candidate list, helper returns `candidatePids[0]` (restart from front). |
| Tracked player **disconnects** mid-tick | Same as death — `isValidPlayer` fails → camera freezes. `onSpectatorPlayerLeave` is for the *spec's* leave path, not the target's; we don't need a separate hook. |
| Press Jump while tracking + only **1 other deployed player** | `idx + 1) % 1 === 0` → cycles back to the same target. No-op visually. Acceptable. |
| Press Jump while tracking + **target list empty** (everyone died simultaneously) | `findNextSpectatorTrackingTarget` returns `null`. Mode stays `in_focus` on the now-stale target pid → camera frozen on last pose. Spec can WASD to exit to free-fly. |
| Spec **exits via triple-tap** while tracking | `exitSpectatorMode` token-bumps the loop → loop returns next tick → tracking state resets. |
| Spec **takes a vehicle** (impossible — they're sealed in cube) | N/A. Body is in the hide room. The vehicle-eject path on enter happens before tracking is even possible. |
| User holds Jump (doesn't release) | `lastJumpEdge` stays true → no rising edge → no cycling. Same as PCT behavior. They have to release + re-press to cycle. |
| User **moves slightly** (controller deadzone twitch) | 0.05 floor on velX/velZ absorbs the noise. PCT uses a similar threshold. |

## Out of Scope (Ship 5b/5c if needed)

- **"Previous target" via in-game input.** PCT only cycles forward; their previous comes from a UI panel. The user's request was framed as "go back and forth" but the chosen pattern is "use the known design" — defer prev until UX feedback says wraparound-only feels insufficient.
- **Smooth lerp transitions** (PCT's `freeCamIsFocusing` / `freeCamIsDefocusing` substates). The simplified two-substate version still uses position lerp via the smoothing factors; the explicit substate machine would add polish on rapid free↔follow transitions but isn't load-bearing for "basic" follow.
- **Mouse-look orbital while tracking.** PCT locks orientation to target facing — no orbital. Mouse-look is ignored while in `"in_focus"` mode.
- **Vehicle-target follow** with adjusted offsets (vehicles need bigger pullback). Defer until SP testing reveals it's needed.
- **Auto-cycle on target death**. PCT freezes; we mirror PCT.
- **Visual indicator** showing which player is being followed. Could add a per-pid HUD line "Following: PlayerName" — defer; the spec can see the player on-screen.
- **Filter by team** for coach-mode use case. Currently both teams cycle-able per user choice.
