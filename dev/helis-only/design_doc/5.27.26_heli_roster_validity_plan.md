## Context

Reported runtime error: **"Received undefined values as arguments"** — fires at spawn time.

Root cause (identified 2026-05-27): [src/ready-dialog.ts:3613-3618](../src/ready-dialog.ts#L3613) `getRosterEntryNameMessage` does a truthy check on `entry.player` but does **not** call `mod.IsPlayerValid`. When the roster rebuilds during a spawn event and a roster entry's `Player` reference has gone stale (e.g., a disconnect or team-switch race between the active-player snapshot and the render), `mod.Message(format, stalePlayer)` triggers the engine error log.

This function fires from spawn-time roster rebuild paths:
- [src/hud.ts:645, 654](../src/hud.ts#L645) — victory dialog roster rebuild.
- [src/ready-dialog.ts:2079, 2110](../src/ready-dialog.ts#L2079) — Ready Dialog roster render.

Both are reached transitively from `OnPlayerDeployed → renderReadyDialogForAllVisibleViewers`.

## Conquest reference pattern

Verified 2026-05-27. Two parts:

**1. The helper at [conquest/src/state/id-helpers.ts:152-155](../../conquest/src/state/id-helpers.ts#L152)**:
```ts
function getUiSafePlayerMessage(player: mod.Player | null | undefined): mod.Message {
    if (!isValidPlayer(player)) return msg(STR_SYS_UNKNOWN_PLAYER);
    return mod.Message(player);
}
```

**2. The caller at [conquest/src/ready-dialog/roster-active.ts:100-104](../../conquest/src/ready-dialog/roster-active.ts#L100)**:
```ts
function getRosterEntryNameMessage(entry: RosterDisplayEntry | undefined): mod.Message {
    if (!entry) return msg(STR_SYS_COUNTER, " ");
    if (entry.player) return getUiSafePlayerMessage(entry.player);
    return msg(STR_SYS_COUNTER, " ");
}
```

Key properties of Conquest's pattern:
- The helper is REUSABLE across any UI-text-rendering site that takes a Player.
- The fallback is the `unknownPlayer` string key ("Unknown") — not an empty string.
- Returns `mod.Message(player)` directly without a wrapping format key (the format `"{0}"` is functionally equivalent but unnecessary).

Helis adaptation note: Conquest uses an `isValidPlayer(p)` helper that wraps `!p && mod.IsPlayerValid(p)`; Helis inlines this check throughout `safeGetSoldierState*` and elsewhere. To match Helis's existing style we inline `!player || !mod.IsPlayerValid(player)` in the helper rather than porting `isValidPlayer` as a third dependency.

## The helper

Insert in [src/state.ts](../src/state.ts) near `safeUndeployPlayer` (added v0.631):

```ts
// UI-safe player-name message wrapper.
// - Returns mod.Message(player) when the Player ref is valid (engine renders the name).
// - Returns the "Unknown" string-key fallback when the Player ref has gone stale.
// - Prevents "Received undefined values as arguments" engine error logs when a stale
//   Player ref is passed to mod.Message (Conquest #94 / #109 heap-pressure mechanism).
function getUiSafePlayerMessage(player: mod.Player | null | undefined): mod.Message {
    if (!player || !mod.IsPlayerValid(player)) return mod.Message(mod.stringkeys.twl.system.unknownPlayer);
    return mod.Message(player);
}
```

## The call-site update

[src/ready-dialog.ts:3613-3618](../src/ready-dialog.ts#L3613):

```ts
// BEFORE
function getRosterEntryNameMessage(entry: RosterDisplayEntry | undefined): mod.Message {
    if (!entry) return mod.Message(mod.stringkeys.twl.system.genericCounter, "");
    if (entry.player) return mod.Message(mod.stringkeys.twl.readyDialog.playerNameFormat, entry.player);
    if (entry.nameKey) return mod.Message(entry.nameKey);
    return mod.Message(mod.stringkeys.twl.system.genericCounter, "");
}

// AFTER
function getRosterEntryNameMessage(entry: RosterDisplayEntry | undefined): mod.Message {
    if (!entry) return mod.Message(mod.stringkeys.twl.system.genericCounter, "");
    if (entry.player) return getUiSafePlayerMessage(entry.player);
    if (entry.nameKey) return mod.Message(entry.nameKey);
    return mod.Message(mod.stringkeys.twl.system.genericCounter, "");
}
```

## Why this is risk-free

- **Valid-Player path**: previously returned `mod.Message(playerNameFormat, player)` rendering as the player's name. Now returns `mod.Message(player)` which also renders as the player's name (format `"{0}"` is equivalent to bare Player). No visible change.
- **Invalid-Player path**: previously fired an engine log; now returns `mod.Message(unknownPlayer)` rendering as `"Unknown"`. The stale row shows "Unknown" instead of breaking the engine log.
- **Empty/missing entries**: unchanged paths (`if (!entry)` and `nameKey` fallback).
- **No new state, no new constants, no new imports.**
