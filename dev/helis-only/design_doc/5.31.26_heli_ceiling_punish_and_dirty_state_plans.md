## Plan 1 — Ceiling-Breach Punishment + Admin Toggle + TWL 2v2 Default HP

### Goal

Three changes to the aircraft ceiling enforcement subsystem and one preset default:

1. Extend the ceiling-breach black-screen warning countdown from 3s to 5s.
2. If the player is still over the ceiling 1 second past the 0 mark of the countdown, apply 10,000 damage to their aircraft (instant destruction).
3. Add an admin panel toggle "Ceiling Punish ON" / "Ceiling Punish OFF" (defaults ON) that gates the destruction step.
4. Set TWL 2v2 (`gameModeHelisLadder`) default Vehicle HP multiplier to 130%.

## Plan 2 — Dirty-State Coloring + Confirm-Required Notice

### Goal

Mirror Conquest's pattern for indicating unsaved Ready Dialog mode-config changes:
1. Color the affected value widgets (game mode value, mode settings value, vehicle health value, vehicles T1/T2 values) **red** when dirty (unsaved), **white/default** when matching confirmed state.
2. Display a notice text widget near the "Confirm & Apply Mode Changes" button when dirty.
3. Notice text mirrors Conquest's string: "Unsaved changes! Press 'Apply Configuration' to save" (will tweak wording for helis context).

### Verified APIs and reference patterns

| Need | Pattern | Reference |
|---|---|---|
| Dirty state shape | `ReadyDialogModeConfigDiffState` type with per-field `*Dirty: boolean` flags + global `hasUnsavedChanges` | `conquest/src/ready-dialog/mode-config-presets.ts:11-22` |
| Build diff state | `buildReadyDialogModeConfigDiffState()` compares `draft` vs `confirmed` State fields | `conquest/src/ready-dialog/mode-config-presets.ts:28-48` |
| Clear dirty on confirm | `applyReadyDialogModePresetForGameMode()` syncs draft → confirmed | `conquest/src/ready-dialog/mode-config-presets.ts:138-157` |
| Per-widget color flip | `mod.SetUITextColor(widget, dirty ? COLOR_NOT_READY_RED : COLOR_WHITE)` | `conquest/src/ready-dialog/mode-config-readout.ts:410` |
| Confirm-required notice text widget | TopLeft anchor, 20px right of Confirm button, full button-row height, CenterLeft text anchor, 12pt, red color | `conquest/src/ready-dialog/dialog-build-mode-config.ts:496-510` |
| Conquest's notice string | `"Unsaved changes! Press 'Apply Configuration' to save"` (string key `twl.readyDialog.unsavedChangesLabel`) | `conquest/src/strings.json:188` |

### Resolved answers

- **Q3**: Three-color scheme — labels white, confirmed values green, dirty values red. Diverges from Conquest's two-color (red+white) pattern to give a stronger positive confirmation signal.
- **Q4**: Notice text hidden when nothing dirty; visible only when at least one field is dirty.
- **Q5**: Color VALUE widgets only (game mode value, mode settings value, vehicle health value, vehicles T1/T2 values). Labels stay white at all times.

### Concrete implementation steps

**Step 2.1 — Add dirty-state type + builder** ([state.ts](../src/state.ts) + [ready-dialog.ts](../src/ready-dialog.ts)):
```ts
type ReadyDialogModeConfigDiffState = {
    hasUnsavedChanges: boolean;
    gameModeDirty: boolean;
    aircraftCeilingDirty: boolean;
    vehicleHealthDirty: boolean;
    vehiclesT1Dirty: boolean;
    vehiclesT2Dirty: boolean;
};

function buildReadyDialogModeConfigDiffState(): ReadyDialogModeConfigDiffState {
    const cfg = State.round.modeConfig;
    const c = cfg.confirmed;
    const gameModeDirty = cfg.gameMode !== c.gameMode;
    const aircraftCeilingDirty = cfg.aircraftCeiling !== c.aircraftCeiling
                                 || cfg.aircraftCeilingOverridePending !== c.aircraftCeilingOverrideEnabled;
    const vehicleHealthDirty = Math.round(cfg.vehicleHealthMultiplier * 100)
                               !== Math.round(c.vehicleHealthMultiplier * 100);
    const vehiclesT1Dirty = cfg.vehicleIndexT1 !== c.vehicleIndexT1;
    const vehiclesT2Dirty = cfg.vehicleIndexT2 !== c.vehicleIndexT2;
    return {
        hasUnsavedChanges: gameModeDirty || aircraftCeilingDirty || vehicleHealthDirty
                          || vehiclesT1Dirty || vehiclesT2Dirty,
        gameModeDirty, aircraftCeilingDirty, vehicleHealthDirty, vehiclesT1Dirty, vehiclesT2Dirty,
    };
}
```

**Step 2.2 — Add render-dirty-state function** ([ready-dialog.ts](../src/ready-dialog.ts) near `updateReadyDialogModeConfigForPid`). Three-color scheme per Q3 answer: dirty = red, confirmed = green, labels stay white (untouched):
```ts
function applyDirtyStateColorsForPid(pid: number): void {
    const diff = buildReadyDialogModeConfigDiffState();
    // VALUE widgets only -- labels stay white at all times.
    const setValueColor = (widgetIdBase: string, dirty: boolean) => {
        const w = safeFind(widgetIdBase + pid);
        if (w) mod.SetUITextColor(w, dirty ? COLOR_NOT_READY_RED : COLOR_READY_GREEN);
    };
    setValueColor(UI_READY_DIALOG_MODE_GAME_VALUE_ID, diff.gameModeDirty);
    setValueColor(UI_READY_DIALOG_MODE_SETTINGS_VALUE_ID, diff.aircraftCeilingDirty);
    setValueColor(UI_READY_DIALOG_VEHICLE_HEALTH_VALUE_ID, diff.vehicleHealthDirty);
    setValueColor(UI_READY_DIALOG_MODE_VEHICLES_T1_VALUE_ID, diff.vehiclesT1Dirty);
    setValueColor(UI_READY_DIALOG_MODE_VEHICLES_T2_VALUE_ID, diff.vehiclesT2Dirty);
    // Notice text visibility (hidden when nothing dirty per Q4)
    const noticeWidget = safeFind(UI_READY_DIALOG_UNSAVED_NOTICE_ID + pid);
    if (noticeWidget) mod.SetUIWidgetVisible(noticeWidget, diff.hasUnsavedChanges);
}
```

Color constants already exist:
- `COLOR_NOT_READY_RED` — used by other "alert" states in the dialog (matches Conquest's pattern)
- `COLOR_READY_GREEN` — used by other "ready" / confirmed states in the dialog
- Default label color stays via `applyReadyDialogLabelTextColor` (white)

**Step 2.3 — Wire into existing update flow**: call `applyDirtyStateColorsForPid(pid)` at the end of `updateReadyDialogModeConfigForPid(pid)` so dirty state updates whenever the dialog refreshes. Also call after Confirm + after Reset.

**Step 2.4 — Add notice text widget to dialog build** ([ready-dialog.ts](../src/ready-dialog.ts) `createTeamSwitchUI`, near where Confirm button is built, around line 1090-1100 area). Position to the LEFT of Confirm button per user spec — needs X math against `confirmButtonX` and adequate width (e.g., 430 game units).

**Step 2.5 — Add string key** ([strings.json](../src/strings.json) under `twl.readyDialog`):
```json
"unsavedChangesLabel": "Unsaved changes! Press 'Confirm & Apply Mode Changes' to save"
```

**Step 2.6 — Add widget ID constant** ([types.ts](../src/types.ts)):
```ts
const UI_READY_DIALOG_UNSAVED_NOTICE_ID = "UI_READY_DIALOG_UNSAVED_NOTICE_";
```

### Validation

- Open Ready Dialog (nothing dirty) — notice hidden, all values **green**, labels white.
- Change game mode preset via `<` / `>` — game mode value text turns **red**. Notice text appears.
- Click Confirm — game mode value turns back to **green**. Notice text hides.
- Click Reset — all dirty state cleared, all values **green** again.
- Change multiple values (game mode + vehicle health) — both turn red, notice visible. Other unchanged values stay green.

### Risk

- Low-medium. Color flipping is a per-tick-cheap visual change. The diff computation iterates a fixed small set of fields. The notice widget is one new widget added to the dialog build.
- Failure modes: dirty state not cleared on Confirm (stuck red); diff computation wrong (false positives/negatives); notice text positioning conflicts with adjacent widgets.

## Plan 2 addendum — Admin Panel row reorder (Tie-Breaker rows to bottom)

## VH layout shift-right issue (resolved in v0.699)

User reported the v0.696→v0.697→v0.698 changes to `vehicleHealthOuterGap` (12 → 8 → 2) produced no visible movement. Confirmed `vehicleHealthOuterGap = 2` shipped but the 10-game-unit total shift was too small to perceive.

**v0.699 fix**: introduced explicit `VH_BLOCK_RIGHT_SHIFT = 40` constant that subtracts from the `inc10X` derivation. All 5 VH widgets (-10, <, value, >, +10) cascade from `inc10X` so the whole block translates as a unit. No widget sizes or button counts changed per user spec ("don't modify the knobs").

User can dial `VH_BLOCK_RIGHT_SHIFT` up (more rightward) or down based on visual feedback after testing v0.699.
