## What's NOT in this list (and why)

User asked: "do any of these impact player performance or reliability in a real way?" Honest answer: no. So this doc is maintainability-only.

If real performance/reliability work is desired, these are NOT cleanup tasks but legitimate features:

**Per-tick hot paths** (already in reasonable shape, but where actual perf cliffs could appear):
- `runAircraftWarningLoop` (5Hz, per-player iteration) — already gated by `IsInVehicle` early-exit
- `updateAllPlayersClock` (1Hz) — already caches `mod.AllPlayers()` once and passes to helpers
- `pollVehicleSpawnerSlots` (1Hz) — cold most of the time
- `runOvertimeCaptureLoop` (4Hz, only active during overtime) — cold most of the match

**Reliability hardening** (preventive, not bug fixes):
- `lastUiSnapshotByPid` cache shape in `overtime.ts` doesn't include color values. v0.737 color writes bypass the cache (correct — but if someone adds a new per-pid value to the overtime HUD later without considering the snapshot, they could ship a stale-render bug). **Add a doc comment** at the snapshot definition warning future contributors.
- Pervasive `try { ... } catch {}` is the established pattern given engine quirks. Not a bug, but means "code that should never error" can silently no-op. No fix; it's the sandbox cost.
