## Context

Reported runtime error: **"Received undefined values as arguments"** — still firing on v0.633 at game start / player join. Two prior fixes closed specific paths:
- v0.632 (Plan A1): `getRosterEntryNameMessage` validity check.
- v0.633 (Plan A3): drop empty-slot `RemoveEquipment` calls in `OnPlayerDeployed`.

Neither fixed the residual error. Investigation 2026-05-27 (research agent diff against Conquest) found that **Helis has ~14 `mod.Message(...)` call sites that pass a raw `mod.Player` ref as a format arg**. Any one of them can fire the engine error if the Player handle goes stale between event-handler entry and message construction (join race, team-switch race, disconnect race, in-vehicle race).

The user explicitly rejected a diagnostic test pass to localize the exact site — they want the error class closed. This plan defends every Player-as-format-arg call site with a single defensive helper, matching the shape of the existing `ownerNameOrKey` ternary at [index.ts:759-762](../src/index.ts#L759).

## Conquest reference pattern

[conquest/src/state/id-helpers.ts:152-155](../../conquest/src/state/id-helpers.ts#L152) defines `getUiSafePlayerMessage(player): mod.Message` — wraps a Player into a Message with an "Unknown" fallback. Conquest uses it in 2 places (the roster path) and avoids this error class elsewhere because Conquest restructured most Player-passing broadcasts away (e.g., Conquest's `OnPlayerEnterVehicle` has zero broadcasts).

Helis keeps the broadcasts (different gameplay surface for the Helis ladder UX). The Conquest-aligned defense for Helis is an analog helper that returns a SAFE FORMAT ARG (not a whole Message) — usable inside any `mod.Message(key, ..., arg, ...)` call.

Helis already uses this exact shape inline at [index.ts:759-762](../src/index.ts#L759):
```ts
const ownerNameOrKey = owner
    ? (mod.IsPlayerValid(owner) ? owner : mod.stringkeys.twl.system.unknownPlayer)
    : mod.stringkeys.twl.system.unassigned;
```

Plan A6 extracts this pattern into a reusable helper and applies it across all 14 sites.

## The helper

In [src/state.ts](../src/state.ts), placed next to `getUiSafePlayerMessage`:

```ts
// Safe format-arg wrapper for mod.Player passed to mod.Message as msgArg0/1/2.
// - Returns the Player handle when valid (engine renders the player's name).
// - Returns the "Unknown" string key fallback when the handle has gone stale.
// - Prevents "Received undefined values as arguments" engine error logs when a stale
//   Player ref is passed as a format arg (Conquest #94 / #109 heap-pressure mechanism).
// Use this anywhere a Player is a FORMAT ARG (msgArg0/1/2). For wrapping a Player as
// the entire message (msg slot), use getUiSafePlayerMessage instead.
function safePlayerArg(player: mod.Player | null | undefined): mod.Player | number {
    if (player && mod.IsPlayerValid(player)) return player;
    return mod.stringkeys.twl.system.unknownPlayer;
}
```

## Independent micro-fix — zero-placeholder subtitle extra args

[src/ready-dialog.ts](../src/ready-dialog.ts):
- Line 3392: `mod.Message(STR_OVERLINE_TAKEOFF_SUBTITLE, offenderToken)` — `takeoffSubtitle` has 0 placeholders.
- Line 3837: `mod.Message(mod.stringkeys.twl.overLine.subtitle, player)` — `subtitle` has 0 placeholders.
- Line 3917: `mod.Message(mod.stringkeys.twl.overLine.subtitle, player)` — same.

All three pass an extra arg the template doesn't use. Fix: drop the arg.

```ts
// BEFORE
mod.Message(STR_OVERLINE_TAKEOFF_SUBTITLE, offenderToken)
mod.Message(mod.stringkeys.twl.overLine.subtitle, player)

// AFTER
mod.Message(STR_OVERLINE_TAKEOFF_SUBTITLE)
mod.Message(mod.stringkeys.twl.overLine.subtitle)
```

## Why this is risk-free

- **Success path**: `safePlayerArg` returns the same Player handle the caller passed → engine renders the player's name as before.
- **Failure path**: stale Player → returns `mod.stringkeys.twl.system.unknownPlayer` → engine renders "Unknown" instead of firing the engine error.
- **Mirrors existing pattern**: `ownerNameOrKey` at [index.ts:759-762](../src/index.ts#L759) uses the exact same shape today. The helper is just the extracted form.
- **Subtitle micro-fix**: removing an unused arg from a template that doesn't reference it has no rendered effect.
- **No new state, no new constants, no per-tick work.**

## Performance

- Each migrated call now does **one extra `mod.IsPlayerValid` check** before `mod.Message`. ~O(1) engine check.
- **Event-driven, not per-tick**. None of the 14 sites are on a hot tick loop:
  - Vehicle entry: 1 event per entry
  - Team switch / ready toggle: 1 event per user action
  - Admin actions: 1 event per click
  - Auto-ready broadcast: rate-limited 3s
- **Bundle**: helper + 14 callsite swaps + 3 subtitle fixes. Expect ~+200-400 bytes net after comment-strip postbuild.

## What this doesn't address

If the error symptom persists after v0.634, the source is NOT a Player format-arg invalidity — it's somewhere else (e.g., NaN from `Math.floor(undefined)` in `OnVehicleSpawned`'s coords, or a string-key lookup returning undefined). That would be a follow-up plan, not a re-do of this one.
